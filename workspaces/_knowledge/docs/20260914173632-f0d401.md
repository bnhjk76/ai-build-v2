# 成功指标与埋点口径 —— 票夹通（TicketWallet）

> 文档版本：v1.0 ｜ 撰写日期：2026-09-14 ｜ 撰写角色：pm（产品经理） ｜ 状态：待评审

> 本文档定义北极星指标、过程指标、质量指标与全部埋点事件的口径，是 tech（埋点实现）与 ops（看板 / 监控）的工作输入。

---

## 1. 指标体系总览

```
北极星（产品价值总量）      周活跃用户中「本月新增开票记录条数」（周记录留存）
 ├── 输入侧过程指标         注册→首条记录转化率、录入一次提交成功率
 ├── 使用侧过程指标         检索功能周使用率、导出功能月使用率、回收站恢复率
 ├── 质量指标（守护）       核心接口 P95 < 500ms、可用性 ≥ 99.5%
 └── 反指标（护栏）         录入放弃率、筛选无结果率、导出失败率
```

设计原则：指标只度量「用户是否持续把开出的票记进票夹」这一核心价值，不以注册量虚荣指标为导向；所有指标可由本文档埋点事件 + 服务端日志直接计算，不引入额外采集面。

## 2. 北极星指标（NSM）

### 2.1 定义（对齐章程 §5 原文：周活跃用户中「本月新增开票记录条数」）

**NSM（周快照）** = 统计周（自然周，周一为起点）内每个活跃用户（WAU 口径见 §4.1）在本自然月累计新增的开票记录条数之和。

- 「新增开票记录」= `invoice_create_success` 事件对应的记录保存成功（编辑、恢复不计，删除进入回收站期间仍计入当月已新增——删除不回减 NSM，避免误删波动扭曲口径）。
- 时间归属：按记录的「创建时间」（服务器时间，东八区）归入自然月。
- **主口径**：总量口径（如上）。
- **辅助口径（人均）**：NSM / WAU = 活跃用户人均本月新增条数，用于跨周期比较（WAU 波动时人均更稳健）。默认主口径为总量，Q3 待确认（见 §8）。

### 2.2 目标值

- 上线后第 1 个完整自然月：人均口径 ≥ 3 条/活跃用户（假设：P1 月均 1–10 张、P2 月均 10–200 张，加权保守取 3；标注待确认，上线后按实际分布校准）。
- 第 3 个完整月：人均 ≥ 4 条（用户从「补录存量」过渡到「随手记增量」的信号）。

### 2.3 为什么选它

- 直接度量价值主张「把开过的票记下来」是否持续发生；
- 对「只注册不使用」「翻看不记录」等虚荣活跃不敏感；
- 周快照粒度能及时反映功能问题（如录入转化下跌当周即可发现）。

## 3. 过程指标与质量指标（含目标）

| # | 指标 | 定义与口径 | 目标 | 计算来源 |
| --- | --- | --- | --- | --- |
| P1 | 注册→首条记录转化率 | 周期内 `account_register_success` 用户为分母；分子 = 其在注册后 7×24 小时内发生 ≥1 次 `invoice_create_success` | ≥ 60% | 埋点 |
| P2 | 检索功能周使用率 | 分母 = WAU；分子 = 本周发生过 ≥1 次 `invoice_filter_apply` 的去重用户 | ≥ 40% | 埋点 |
| P3 | 导出功能月使用率 | 分母 = MAU；分子 = 本月发生过 ≥1 次 `export_success` 的去重用户 | ≥ 20% | 埋点 |
| P4 | 录入表单一次提交成功率 | 分母 = `invoice_create_submit`；分子 = 首次提交即 `invoice_create_success`（同一表单会话内无 `invoice_create_fail` 前置） | ≥ 95% | 埋点 |
| Q1 | 核心接口 P95 延迟 | 登录、列表查询、创建记录三类接口的服务端处理延迟 P95（月度） | < 500ms | 服务端监控（ops 落地） |
| Q2 | 可用性 | 月度成功请求分钟占比（5xx 与超时视为不可用） | ≥ 99.5% | 服务端监控（ops 落地） |
| R1 | 录入放弃率（护栏） | 进入录入页（`invoice_create_start`）后 30 分钟内未产生 `invoice_create_success` 亦未主动关闭表单的比例 | 观察 < 20% | 埋点 |
| R2 | 筛选无结果率（护栏） | `invoice_filter_apply{has_result:false}` 占全部筛选次数比例 | 观察 < 30%（过高说明默认筛选或数据引导有问题） | 埋点 |
| R3 | 回收站恢复率（观察） | `recycle_restore_success` / `invoice_delete_success`（30 天窗口） | 观察（高恢复率 = 删除交互需加警示） | 埋点 |

## 4. 基础口径定义（分母 / 时间 / 归属）

### 4.1 活跃用户

- **WAU**：自然周（周一起 7 天，东八区）内发生 ≥1 次已认证服务端会话的去重 user_id。已认证会话 = 登录后任意页面 / API 成功请求（以服务端日志为准，不依赖前端心跳）。
- **MAU**：自然月内同理。
- 回收站、登录失败不计为活跃（无有效会话）。

### 4.2 事件通用属性

所有埋点事件统一携带：`user_id`（注册用户 ID）、`session_id`、`event_time`（东八区）、`client`（web / mobile-web）、`app_version`。禁止携带发票业务字段值（抬头、号码、金额等一律不进埋点，见 §7 隐私）。

### 4.3 幂等与去重

- 同一 `session_id` 内 100ms 重复上报的相同事件按一次计（前端防抖 + 后端去重）。
- 指标计算一律按 user_id 去重（使用率类）或按事件计数（成功率类），在 SQL 口径层固定，不允许看板层自行解释。

## 6. 核心漏斗定义

1. **首录漏斗**：`account_register_success` → `invoice_create_start` → `invoice_create_success`（对应 P1 ≥ 60% 与 R1 < 20%）。
2. **检索漏斗**：`invoice_list_view` → `invoice_filter_apply` → `invoice_detail_view`（观察筛选后是否深入查看，验证 G2 体验）。
3. **导出漏斗**：`stats_view`/`invoice_list_view` → `export_click` → `export_success`（P3 ≥ 20% 的过程拆解）。

## 7. 数据治理与隐私底线

- **最小采集**：埋点不携带任何发票业务字段值（抬头、号码、金额、备注、附件内容）；参数仅含维度枚举、计数与耗时。
- **身份**：埋点 user_id 为系统内部 ID，不使用邮箱 / 手机号明文。
- **传输**：埋点上报与业务流量一致走 HTTPS（G4）。
- **保留期限**：明细埋点保留 12 个月，聚合指标长期保留（ops 备份策略落地）。
- **用户数据权利**：用户可导出自己的全量记录（F10）；删除走回收站 30 天后物理清除（F12），埋点中的 `record_id` 在物理清除后失去关联意义（不反查）。

## 9. 看板与复盘机制（建议）

- **周报看板**：NSM（总量 + 人均）、P1–P4、R1–R3，按周切片，周一出上一自然周数据。
- **月度复盘**：漏斗三件套 + 目标达成表（对照 §3 目标列），异常指标附 top 失败 reason 分布。
- **告警联动**：P4 一次提交成功率单日 < 90% 或 R2 单周 > 50% 时触发产品侧告警（与 ops 告警通道共用，阈值落地见 ops 文档）。
