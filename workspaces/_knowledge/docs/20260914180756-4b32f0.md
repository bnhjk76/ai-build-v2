# 工单体系（分级 / SLA / 升级 / 回访）—— 票夹通（TicketWallet）

> 文档版本：v1.0 ｜ 撰写日期：2026-09-14 ｜ 撰写角色：support（客服负责人）｜ 状态：待评审

## 1. 背景

工单是客服体系的运营中枢：承接 FAQ 解决不了的问题，驱动 tech/ops 修复，并沉淀为知识库与产品反馈。票夹通为免费单机产品，工单体系与 ops 告警分级（P0–P2）**对齐而非重复**：告警分级面向系统指标（拨测、健康检查、自动触发），工单分级面向**用户影响**（用户报障、咨询、投诉）。映射关系：工单 P0/P1/P2 分别对应 ops 告警 P0/P1/P2 并触发同一条值班升级路径；工单 P3（咨询建议类）无告警对应。

MVP 阶段工单载体从轻：共享邮箱 + 工单登记表（或轻量 issue 跟踪工具）即可运转，字段规范先行，工具可后补。

## 2. 工单来源与录入规范

**来源**：① 客服邮箱/登录页客服入口的每一次人工交互（FAQ 自助解决的不建单）；② ops 告警自动转单（P0/P1）；③ feedback-loop 被动信号触发（见该文档 §2.4，如某错误码频次异常）。

**录入字段规范**（缺项标「待补」）：

| 字段 | 要求 |
| --- | --- |
| 工单号 | `TW-YYYYMMDD-序号`，全局唯一 |
| 用户标识 | 脱敏留存（`a***@x.com` / `138****1234`），与用户提供原文分离存放 |
| 主题 | 一句话现象描述 |
| P 级 | 按 §3 定级，定级人署名 |
| 关联功能 | F01–F15 功能 ID（定位责任域） |
| 关联错误码 | api-design §6 的 code（如有） |
| X-Request-Id | 客服从服务端日志反查获得（按「用户+时间」检索 pino 日志） |
| 复现信息 | 时间、页面、步骤、截图、浏览器/设备 |
| 处置记录 | 时间线式追加，每次更新署名+时间 |

## 3. 分级标准（P0–P3）

| P 级 | 定义 | 典型示例 | 与 ops 告警对应 |
| --- | --- | --- | --- |
| **P0 严重** | 全站不可用，或发生数据安全事件 | 服务整体打不开（SYS_002 持续）；疑似数据泄露/越权；数据库不可用 | ops P0 |
| **P1 高危** | 核心功能不可用或数据正确性受损，无绕行方案 | 无法登录/无法录入/列表打不开；汇总口径计算错误；密码重置/注销等涉账号安全的专项（sop §5.1） | ops P1 |
| **P2 中危** | 部分功能异常但有绕行方案，或影响可容忍 | 附件上传失败（可重试/可后补）；导出失败；某筛选条件失效；反复出现 SYS_001；注销申请等人工时效类 | ops P2 |
| **P3 低危** | 咨询、建议、文案与体验问题 | 功能建议（OCR/进项/协作）；文案歧义；重复录入提醒类需求 | 无（不触发告警） |

**定级三问**（辅助一线快速定级）：① 影响的是「所有用户的核心路径」还是「个别功能」？② 有没有立即可用的绕行方案？③ 是否涉及数据丢失/泄露风险？——涉及③一律不低于 P1，确认属实升 P0。

**改级规则**：处置中影响面变化可改级，改级必须在工单中留痕（原因+时间+操作人）；只升不降由一线执行，降级需负责人确认。

## 4. SLA（响应 / 解决 / 通报）

工作时间：周一至周五 9:00–18:00（东八区）。P0/P1 的响应时钟 **7×24 计算**（由告警与值班路径承接）；P2/P3 仅在工作时间内计时。

| P 级 | 首次响应 | 解决目标 | 进展通报节奏 |
| --- | --- | --- | --- |
| P0 | ≤ 15 分钟（7×24） | ≤ 2 小时恢复服务（对齐 RTO 2h） | 每 30 分钟向受影响用户/公告通报 |
| P1 | ≤ 30 分钟（7×24 转值班） | ≤ 4 小时解决，或给出可用绕行方案 | 每 2 小时 |
| P2 | ≤ 2 小时（工作时间） | ≤ 24 小时（1 个工作日） | 每日 1 次 |
| P3 | ≤ 8 小时（工作时间） | ≤ 72 小时（3 个工作日）答复，或明确纳入排期并告知预期 | 关单前 1 次 |

补充口径：

- 「解决」= 用户侧功能恢复或给出被用户接受的绕行方案；P3 的「解决」可以是「明确答复 + 已回流产品池」；
- 非工作时间到达的 P2/P3，响应时钟从次日 9:00 起算；
- P0/P1 在工作时间内由客服主导通报；非工作时间由 ops 值班按告警路径处置，客服次日 9:00 前完成补位回访与工单补录。

## 5. 升级路径

### 5.1 四层升级链

```
L1 一线客服 ──> L2 客服负责人 ──> L3 tech/ops 值班 ──> L4 发起人 / 主 Agent
```

| 层 | 触发条件 | 职责 |
| --- | --- | --- |
| L1 一线客服 | 全部工单首响与 FAQ 可解问题 | 定级、话术、建单、跟踪 |
| L2 客服负责人 | P1 以上；投诉 C 类；补偿审批；降级确认；SLA 超时 | 复核定级、协调资源、对外口径把关 |
| L3 tech/ops 值班 | P0/P1 技术处置；安全事件 | 修复、回滚、发布公告口径 |
| L4 发起人 / 主 Agent | P0 超 2 小时未恢复；数据安全事件确认；涉及章程范围变更 | 决策（含是否回滚版本、是否公告） |

### 5.2 自动升级规则

- 首响超时达 SLA 的 50% → 自动升级一层并提醒；
- 解决超时达 SLA 的 50% → 自动升级一层，P0/P1 同时电话通知；
- SLA 全量超时 → 直升 L4。

### 5.3 电话升级兜底（对齐 ops 单人值班风险）

非工作时间或即时通讯无响应时，P0/P1 必须启用**电话直呼**值班人与负责人，不允许仅留言等待。单人值班的覆盖缺口是已知风险（ops 口径），客服侧对冲：① P0 工单 30 分钟无响应即电话升级上一层；② 升级动作全部留痕（时间、呼叫对象、结果）。

## 6. 工单生命周期

```
新建 → 已受理 → 处理中 → 待用户确认 → 已解决 → 已关闭
                    ↑__________ 重开（关单后 7 日内同类问题）__________↓
```

- **待用户确认**：处置完成但需用户验证（如「请重试导出」）；发出确认请求后 3 个工作日无回复可自动关单（P3）或电话回访（P1/P2）；
- **重开**：关单后 7 日内同一问题复发 → 重开并**自动升一级**（最高 P1），原 SLA 重新起算；
- **已关闭**：回访完成（P1 以上强制回访）后进入归档，只读；
- 所有状态流转留痕（时间、操作人、原因）。

---

## 7. 满意度回访

- **触发**：工单关闭后 24 小时内发送评价邀请（P1 及以上、全部投诉工单为强制回访；P2/P3 抽样 ≥30%）；
- **形式**：1–5 分评分 + 可选文字留言；
- **低分处置**：评分 ≤ 2 → 工单自动重开为「回访复核」，客服负责人 1 个工作日内人工回访，输出原因归类（话术问题 / 解决不彻底 / 态度问题 / 预期落差）；
- **回访话术**：

  > 您在票夹通提交的问题（工单号 {id}）已处理完毕。请花 10 秒为本次服务打分（1–5 分，5 为非常满意）。如问题未真正解决或您还有补充，直接回复本邮件即可重新打开工单。

- **度量**：月度 CSAT（目标 ≥ 4.2 / 5）、重开率（目标 ≤ 8%）、低分工单 100% 复盘；数据进入 `feedback-loop.md` 月度报告。
