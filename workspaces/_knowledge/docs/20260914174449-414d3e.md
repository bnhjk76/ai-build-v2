## 3. 页面详情

### P01 登录页（`/login`）

**目的**：已注册用户凭账号标识 + 密码进入私有票夹；是安全旅程（J4）的入口。

**关键元素**：
- 居中卡片（移动全宽）：产品标识「票夹通」+ 一句话价值文案「你开过的每一张发票，都在这里」。
- 表单：账号（邮箱/手机号，单输入框，自动识别类型）、密码（可切换明文/密文眼睛按钮）、「记住我 7 天」勾选（默认勾选；公共设备可取消，对应 J4 异常 A 建议）。
- 主按钮「登录」（loading 态防重复提交）；下方文字按钮「没有账号？注册」。
- 页脚安全声明小字：「数据通过 HTTPS 加密传输，仅你本人可见」。

**状态设计**：
- 默认：空表单、焦点在账号输入框。
- 加载：提交后按钮 spinner，输入禁用。
- 错误（行内）：账号格式不合法——输入框红边 + 下方红字。
- 错误（表单级 Toast）：「账号或密码错误」（不泄露哪个字段错，F02 验收）；连续 5 次后第 6 次：警示 Toast「账号已锁定，请 10 分钟后重试」，同时禁用登录按钮并显示倒计时（若有剩余时间信息）。
- 空态：不适用。
- 辅助：忘记密码场景显示「忘记密码？请联系客服」+ 客服入口（MVP 无自助找回，US02 异常路径；Q1 决策后替换）。

### P02 注册页（`/register`）

**目的**：一步完成注册并自动登录，直达空票夹（转化第一步）。

**关键元素**：
- 表单：账号（邮箱或手机号）、密码（8–20 位、须含字母与数字，规则文字常驻输入框下方）、确认密码（实时比对）、主按钮「注册并进入」。
- 已有账号去「登录」的文字链接。
- 密码强度不做分级展示（MVP 克制），仅做合规与否提示。

**状态设计**：
- 默认：空表单。
- 错误（行内，失焦即校验）：邮箱缺 @ / 手机号非 11 位 / 密码 6 位纯数字 / 两次密码不一致——定位到出错字段（F01 验收）。
- 错误（表单级）：邮箱已注册——表单顶部警示条「该邮箱已注册，请直接登录」+「去登录」链接（一键跳转，US01 AC2）。
- 成功：自动登录 → 跳转 `/invoices`（空态引导）。
- 加载：按钮 spinner。

### P03 票夹列表页（`/invoices`，登录后首页）—— 核心页面

**目的**：回答「我开过哪些发票」的主界面：纵览、检索、导出、删除的作业台。

**关键元素**：
- 页头：标题「我的票夹」+ 总条数（如「共 45 张」）+ 主按钮「＋新增发票」。
- 筛选区（常驻吸顶，不折叠）：月份选择器、抬头关键字输入、金额区间（min/max 两个数字框）、类型多选（电子/纸质/专票/普票四个胶囊，可组合）、状态多选（正常/作废/红冲）；「筛选」主按钮 + 「清除筛选」文字按钮；生效中的条件以标签形式回显（可单个点 × 移除）。
- 工具行：当前结果计数（「筛选出 12 张」）+ 右侧「导出当前筛选」按钮 + 「眼睛」脱敏切换（F13）+ 每页 20 条分页控件。
- 列表表格（桌面）/ 卡片列表（移动）：
  - 桌面列：开票日期 ｜ 抬头 ｜ 类型标签 ｜ 状态标签 ｜ 发票号码（默认 `****5678`）｜ 价税合计（右对齐 tabular-nums）｜ 附件标记（📎×n）｜ 操作（删除）。
  - 移动卡片：首行「抬头 + 价税合计」，次行「日期 · 类型 · 状态」，末行「号码(掩码) · 📎」；点击卡片进详情。
- 整行点击进详情（操作列的删除按钮阻止冒泡）。

**状态设计**：
- 默认：全量按开票日期倒序、每页 20 条；筛选条件为空。
- 加载：表格区 5 行骨架屏（shimmer）；翻页时同样式。
- 空（首录型，F14）：新用户无任何记录——插画 + 「录入你的第一张发票」+ 主按钮「＋新增发票」+ 一句价值文案「2 分钟建好你的开票台账」。
- 空（筛选无果型）：有数据但当前条件无结果——「没有符合条件的发票，试试调整筛选」+「清除筛选」主按钮（两种空态必须区分，F08 验收）。
- 错误：列表加载失败——表格区整页错误态（图标 + 「加载失败，请检查网络」+「重试」按钮）；筛选提交 min>max 时行内红字「最小金额不能大于最大金额」，不发起请求。
- 无权限：未登录 302 → `/login`；会话过期 401 → Toast「登录已过期」后跳登录（回跳原 URL）。
- 脱敏态：号码列默认掩码；点眼睛切换全显（偏好记忆，详见 design-spec §6）。

### P04 发票详情页（`/invoices/:id`）

**目的**：完整呈现一条记录的全部字段与附件，是编辑/删除/附件管理的操作中心。

**关键元素**：
- 面包屑「票夹 / 发票详情」+ 返回按钮。
- 信息卡按 4.1 对象模型分组展示（身份组/交易组/分类组/备注组），字段值 `font-body-lg`；**号码完整显示**（已登录本人场景，F13）。
- 状态标签醒目置顶（作废/红冲记录用对应色标签，红冲金额显示负值样式 `-2,000.00`）。
- 附件区：缩略图网格（图片）+ PDF 文件行；点击新开预览；「上传附件」入口（≤3 个，满 3 置灰）。
- 操作区：主按钮「编辑」（M2）、次按钮「删除」（弹二次确认）。
- 元信息：创建时间、更新时间（caption 灰字）。

**状态设计**：
- 默认：全字段 + 附件渲染完成。
- 加载：整卡骨架屏（字段行骨架 + 附件位骨架）。
- 空：不适用（无记录走「不存在」态）。
- 错误：id 不存在或非本人记录——统一「记录不存在或已删除」整页态 +「返回票夹」按钮（不暴露存在性，见 IA §6）；附件加载失败——缩略图占位 +「重新加载」。
- 无权限：未登录/过期同 P03 处理。

### P05 发票表单页（新增 `/invoices/new` ／ 编辑 `/invoices/:id/edit` 复用同一组件）

**目的**：把一张开出的发票 2 分钟内结构化沉淀（G1），编辑为同一表单的复用态。

**关键元素**：
- 页头：「新增发票」/「编辑发票」+ 返回；表单主体限宽 640px 居中。
- 字段（11 个，按填写动线排序）：开票日期（日期控件，max=今天）→ 抬头（文本，带历史联想 F15：输入 ≥2 字出下拉）→ 发票号码（数字）→ 发票代码（选填，标注「数电票可不填」）→ 金额 → 税额 → **价税合计（只读灰底，实时=金额+税额）** → 票种（专票/普票 单选胶囊）→ 介质（电子/纸质 单选胶囊）→ 状态（默认「正常」）→ 备注（多行文本）。
- 附件上传区（M2）：拖拽/点击上传，格式与限制说明常驻（「jpg/png/webp/PDF，单个 ≤10MB，最多 3 个」）；已传项显示缩略图 + 进度条 + 删除。
- 底部按钮组：主按钮「保存」（loading 态）、次按钮「取消」（有未保存内容时弹确认）。

**状态设计**：
- 默认：日期预填今天、状态预填「正常」、价税合计显示 `0.00`；编辑态回填原值且不可改「创建时间」。
- 加载（编辑态）：进入时字段区骨架屏；保存时按钮 spinner。
- 错误（行内，失焦即时 + 提交全量）：必填为空 / 金额 ≤0 / 未来日期 / 号码位数 8–20 外 / 代码超 20 位——逐字段红边 + 红字，焦点跳到第一个错误字段；**已填内容全部保留**（US04 异常）。
- 错误（网络）：提交失败 Toast「保存失败，请检查网络后重试」；表单数据本地暂存不丢失，可原样重试。
- 空：附件区 0 个时显示上传引导占位。
- 无权限：未登录 302；编辑回收站内记录不可达（无入口，路由兜底 404 态）。

### P06 汇总统计页（`/stats`）

**目的**：不用手工累加，直接回答「本月/本年开了多少」（G3 上半场）。

**关键元素**：
- 页头：「汇总统计」+ 数据口径说明入口（「口径说明」链接展开折叠：有效金额=正常票金额+红冲负数冲减；作废只计张数——DP2 台账透明）。
- 卡片一「本月」：本月张数、有效金额（大数字 `font-num-xl`）、作废张数、红冲张数。
- 卡片二「本年」：本年张数、有效金额、作废张数、红冲张数（口径东八区自然年）。
- 类型分布区块：票种 × 介质四象限（电子普票/纸质普票/电子专票/纸质专票）的张数与金额，用横向条形（非复杂图表，轻量实现）。
- 页头主按钮「导出明细 CSV」（F10，导出=汇总口径明细）。

**状态设计**：
- 默认：当前自然月/年数据渲染。
- 加载：数字位与分布条骨架。
- 空：全年无记录——卡片显示 `0`、分布图为空槽位 + 文案「暂无开票记录」，**不报错**（F09 验收）。
- 错误：加载失败整页错误态 + 重试；导出失败 Toast + 重试入口。
- 导出超限（>5000 条）：警示弹窗「超过单次导出上限 5000 条，请缩小筛选范围」（建议去列表页加月份筛选），导出中止不崩溃。
- 无权限：未登录/过期 302/跳登录。

### P07 回收站页（`/recycle`）

**目的**：误删兜底（J3）：让用户 30 天内能找回记录，并对不可恢复有预期。

**关键元素**：
- 页头：「回收站」+ 说明文字「删除的记录将保留 30 天，到期自动清除」。
- 列表（按删除时间倒序）：抬头 ｜ 原开票日期 ｜ 价税合计 ｜ 删除时间 ｜ 剩余可恢复天数（「剩余 18 天」，≤7 天转 `color-warning-600` 预警色）｜ 操作：「恢复」（主操作）、「彻底删除」（危险文字按钮）。
- 空态：「回收站是空的」+ 引导返回票夹。

**状态设计**：
- 默认：倒序列表渲染。
- 加载：行骨架。
- 空：见上。
- 错误：加载失败错误态 + 重试；恢复失败 Toast「恢复失败，请重试」；彻底删除需二次确认弹窗（红色警示文案「删除后不可恢复，附件同时清除」）。
- 无权限：未登录/过期 302/跳登录。
- 规则：回收站内记录无「编辑」入口；不参与任何列表/筛选/汇总/导出口径（IA §4.4）。

### P08 全局系统层（横切）

**目的**：承接所有页面的公共异常与系统状态，避免各页重复实现不一致。

**组成与状态**：
- **404 页**：访客与登录用户通用——「页面不存在」+ 返回首页按钮（登录用户回 `/invoices`，访客回 `/login`）。
- **500/服务错误页**：「服务开小差了」+「重试」按钮 + 稍后自动重试提示。
- **网络中断层**：检测 offline 事件——顶部常驻警示条「网络已断开，操作可能失败」（不阻断浏览已加载数据）。
- **会话过期**：任意页面收到 401 → Toast「登录已过期，请重新登录」→ 跳 `/login` 并携带回跳地址（F02 验收回跳原 URL）。
- **全局 Toast 容器**、**全局确认弹窗**：规格见 design-spec §5。

## 5. 验收标准与后续行动

### 5.1 验收标准

- [x] 8 个页面覆盖 F01–F14 全部功能的界面入口，无功能悬空
- [x] 每页具备五状态定义（不适用项已注明理由）
- [x] 两种空态（首录型/筛选无果型）明确区分（F14/F08）
- [x] 异常路径与 features.md 验收条目一一对应（锁定、越权、断网、超限、min>max）
- [x] 脱敏规则与 design-spec §6.2 矩阵一致（列表掩码、详情/导出完整）

### 5.2 后续行动

1. tech 按 P01–P08 拆组件与 API 对接点；E2E 用例按各页「状态设计」覆盖异常分支。
2. 线框图 `wireframes.md` 对 P01/P03/P05/P06/P07 提供布局结构。
3. support 依据 P05/P07 的错误文案口径预写 FAQ（保存失败、恢复失败、导出超限）。
4. 若 Q1（忘记密码）纳入 M2，增补 `/forgot-password` 页面条目并升版本。
