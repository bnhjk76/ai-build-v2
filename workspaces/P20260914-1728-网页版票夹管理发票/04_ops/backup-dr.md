## 1. 背景

票夹通存的是**发票台账与发票原件（图片/PDF）**，属于用户不可再生的财务凭证数据：发票记录可人工重录，但原件丢失不可逆。单机部署意味着「整机故障=全量风险」，因此备份是 M3 上线的**一票否决项**（M3 DoD：备份恢复演练一次成功）。本方案以 engineering-plan §6.3 为基线，给出可执行的备份内容、调度、恢复流程与演练制度，守住两条底线：**RPO ≤24h、RTO ≤2h**（整机重建口径）。

## 2. 目标：RTO / RPO 矩阵

| 场景 | RPO（可容忍数据丢失） | RTO（恢复时长目标） | 达成手段 |
| --- | --- | --- | --- |
| 应用发布失败/坏版本 | 0（数据不动） | ≤5 分钟 | 镜像 tag 回退（deployment.md §5.1，CD 自动回退 30 秒判定） |
| 迁移失败/库结构损坏 | 0（部署前 pre-deploy dump） | ≤2 小时 | `prisma migrate resolve` + 恢复部署前 dump（deployment.md §5.2） |
| 误删单条发票/附件（回收站已清空） | ≤24h（回到最近备份点） | ≤2 小时 | 从最近备份选择性恢复（§4.3） |
| 整机故障（磁盘/系统损毁） | ≤24h | ≤2 小时 | Compose 一键重建 + 最近备份恢复（§4.1） |
| 误操作批量删除被备份同步传播 | 受对象存储版本控制保护（≤14 天内可回） | ≤2 小时 | 版本化桶回滚旧版本（§3.4） |

说明：RPO 24h 是**个人工具可接受阈值**（engineering-plan §6.3 原文口径），代价是每日备份窗口内新增数据可能丢失；用户可在产品内依赖回收站 30 天机制兜底人为误删（F12），备份兜底的是「机器级灾难」。

## 3. 备份策略

### 3.1 备份内容清单

| # | 内容 | 方式 | 说明 |
| --- | --- | --- | --- |
| 1 | PostgreSQL 全库（users/sessions/invoices/attachments/events） | `pg_dump -Fc`（自定义压缩格式，支持选择性恢复与 pg_restore 并行） | 含 schema 与数据；`-Fc` 单文件便于加密传输 |
| 2 | 附件卷 `/data/attachments`（发票图片/PDF 原件） | `rsync -a` 增量镜像 | **不带 `--delete`**（防误删传播，孤儿文件靠 §3.5 对账清理） |
| 3 | 配置与密钥：compose.yaml、Caddyfile、`.env` | git 版本化（结构与模板）+ `.env` **加密副本**入备份 | `.env` 含 DB 口令与 session 盐，用独立口令 AES-256 加密，口令离线保管（密码管理器），**不与备份同存** |
| 4 | 前一日 pino 日志归档 | gzip 打包随备份上传 | 排障留痕，14 天保留 |

### 3.2 调度（宿主 crontab，东八区）

1. **02:00 数据库备份**：`pg_dump` → 校验（`pg_restore --list` 可读 + 行数抽查 invoices/users 计数写入清单文件）→ openssl AES-256 加密 → 上传异机 → 清理本地暂存（仅保留最近 3 份本地热备）；
2. **03:00 附件同步**：rsync 增量至异机（或对象存储同步工具）；完成后抽样比对 `find | wc -l` 文件数与总字节数，偏差 >1% 告警 P1；
3. **03:30 备份结果上报**：成功/失败 + 产物大小 + 校验结论推送值班频道（monitoring.md §3.3 巡检聚合当日核验）；**失败即 P1 告警**（monitoring.md §2.1 业务指标）；
4. **02:00 CD 部署前备份**：发布流程内的 pre-deploy dump（cicd.md §5.2 步骤 3），独立于例行备份。

### 3.3 保留策略

- 异机保留**最近 14 份**（约 14 天滚动），超期自动清理；
- 本地 `/data/backups` 仅保留最近 3 份（磁盘与快速恢复平衡）；
- 里程碑节点（M3 验收版等）的 dump 手动标记**保留 90 天**（冻结基线）。

### 3.4 异机存放（关键设计：防误删传播）

首选**对象存储版本化桶**（OSS/S3/Cloudflare R2 免费层，10GB 内零成本，符合 T5）：

1. 桶开启**版本控制**：即使 rsync/同步把删除操作传播上来，旧版本对象仍可按版本找回（§2 矩阵最后一行的保障）；
2. 桶策略：私有读写，仅备份脚本凭证可访问；传输 TLS；
3. 备选：第二台廉价 VPS（rsync 目标）——无版本控制能力，仅作兜底；
4. 每季度演练时顺带验证「从桶下载 → 解密 → 恢复」全链路（§5）。

### 3.5 一致性与对账

1. **先 DB 后附件**的备份顺序可能产生「附件已入库但 rsync 未带上」的瞬时不一致——影响有限（下一日 rsync 补齐），演练时以「附件对账脚本」核验：比对 DB storageKey 集合与备份目录文件集合，缺失清单输出；
2. 孤儿文件（DB 已删、备份目录残留，architecture §6.5 遗留物）：对账脚本按月清理异机孤儿，**清理前打印清单人工确认**。

## 4. 恢复流程

### 4.1 整机重建（RTO ≤2 小时，对应单机故障）

前置：新 VPS 就绪 + 备份凭证与解密口令可取。

1. 新机按 deployment.md §4 步骤 1–4 完成初始化与配置落位（DNS TTL 600，切换生效 ≤10 分钟）；
2. 从对象存储下载最近一份加密 dump 与附件镜像至 `/data/backups`；
3. 解密 dump（`openssl enc -d -aes-256-cbc`）→ `pg_restore -c -d <db>`（`-c` 先清理再建）；
4. rsync 附件镜像回 `/data/attachments`，核对文件数与备份清单一致；
5. `docker compose up -d`（跳过 migrate deploy 之外步骤，若备份 schema=当前代码版本则 migrate deploy 应为空操作）；
6. 验证：health 200 → 登录（用备份内已有账号）→ 列表数据与备份清单行数一致 → 抽 1 个附件可下载预览；
7. 记录实际 RTO/RPO 至演练记录表（§5.2），切换 DNS 观察 30 分钟。

### 4.2 数据库恢复（迁移失败/库损坏）

1. 停 api 容器（`docker compose stop api`，防止写入干扰）；
2. 恢复目标 dump：`pg_restore -c -d <db> /data/backups/<dump>`；
3. 回退应用镜像至与该 dump schema 匹配的 tag（deployment.md §5.1）；
4. `up -d` + health 验证 + 冒烟；
5. 复盘迁移为何未经 staging 充分验证（cicd.md §5.3 纪律 2）。

### 4.3 单记录/单附件恢复（用户误删，回收站已清空）

1. 在**隔离环境**（staging 或本机 docker）恢复最近 dump；
2. 按用户提供的线索（日期/金额/抬头）定位误删行，导出该行 SQL/JSON 与对应附件文件；
3. 经用户确认金额与号码后，由 support 走运维通道插回生产库（或引导用户手工重录——发票字段少，重录 2 分钟内，多数场景优先推荐重录，物理恢复仅用于附件原件找回）；
4. 全程留《故障记录表》登记，不向其他用户数据触碰（账号隔离纪律）。

## 5. 恢复演练

### 5.1 节奏与范围

- **季度一次** + **M3 首演**（M3 W5 DoD：备份恢复演练一次成功）；重大架构变更（存储切换 S3Provider、PG 大版本升级）后加演一次；
- 演练内容=§4.1 整机重建全流程（在隔离 VPS 或本地等效环境），**不在生产机上演练**；
- 演练后的检查单：health/登录/列表行数/汇总口径（38,000 案例可复算）/附件预览/CSV 导出六项全过才算成功。

### 5.2 演练记录表（模板，随演练归档）

| 项 | 记录 |
| --- | --- |
| 日期 / 执行人 | 2026-__-__ / ops |
| 使用的备份点 | dump 文件名 + 附件镜像时间戳 |
| RPO 实测 | 备份点距演练时刻 = __h（≤24h 达标） |
| RTO 实测 | 从新机就绪到验证通过 = __min（≤120min 达标） |
| 六项检查单结果 | health / 登录 / 行数 / 口径 / 附件 / 导出 |
| 发现的问题 | （如：解密口令不在位、附件数偏差…） |
| 结论与行动 | 通过/不通过 + 整改项与期限 |

### 5.3 备份有效性日常保障（不等演练）

1. 每日备份脚本内置校验（§3.2 步骤 1 的 `pg_restore --list` + 计数清单），校验失败等同备份失败告警；
2. 巡检脚本每日核验产物存在性与大小环比（偏小 >30% 告警——可能是空 dump）；
3. 解密口令与备份凭证每季度演练时实际使用一次（防止「有备份、口令失效」的最糟情况）。
