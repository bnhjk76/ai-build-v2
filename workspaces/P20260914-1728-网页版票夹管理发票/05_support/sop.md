## 1. 背景

票夹通一期为**免费产品**：无支付、无订单，因此不存在常规意义的退款场景；补偿以「非现金工具箱」为主。产品为单机轻量部署，客服体系同步轻量化：**一个客服邮箱 + 登录页客服入口 + FAQ 自助**三层结构，P0/P1 严重故障依赖 ops 拨测告警与值班升级兜底（非靠用户上报）。

**服务渠道与服务时间（MVP）**：

| 渠道 | 地址/入口 | 时间 | 说明 |
| --- | --- | --- | --- |
| 客服邮箱 | `support@ticketwallet.example`（占位，上线前替换） | 工作日 9:00–18:00（东八区）受理 | 一切人工入口的汇总点 |
| 登录页客服入口 | 登录页预留位（pm 已留位，文案与 designer 对齐） | 同上 | 主承接「忘记密码」等登录前问题 |
| FAQ 自助 | 站内 FAQ 页 | 7×24 | 第一道防线 |
| 故障主动发现 | 拨测 + 告警 → ops 值班 | 7×24 | P0/P1 不依赖用户上报，客服同步公告口径 |

工作时间定义：周一至周五 9:00–18:00（东八区）；非工作时间的 P0/P1 由告警触发 ops 值班路径（含电话升级兜底），客服次日 9:00 补位回访。

## 2. 接待 SOP

### 2.1 五步标准流程

```
首响安抚 → 信息采集 → 定性分级 → 处置/流转 → 关单回访
```

1. **首响（工作时间内 2 小时内，紧急类按 ticketing SLA）**：确认收到 + 给出自助路径。首响模板：

   > 您好，感谢联系票夹通客服，已收到您的问题。【如问题明确，直接给 FAQ-Qxx 话术；否则如下】为了尽快帮您处理，请提供：① 注册账号（邮箱/手机号）；② 问题发生的页面和大致时间；③ 具体操作步骤；④ 报错提示截图（如有）。

2. **信息采集清单**（按需，不强求全量）：

   | 项 | 要求 | 用途 |
   | --- | --- | --- |
   | 注册账号 | 用户提供明文（客服记录时脱敏留存，如 `a***@x.com`） | 日志反查、身份关联 |
   | 发生时间 | 精确到分钟级更佳（东八区） | 按「用户+时间」反查服务端日志（X-Request-Id 通常由客服从日志侧获得，不要求用户提供） |
   | 页面与操作步骤 | 文字或截图 | 复现与定性 |
   | 报错提示原文/截图 | 与错误码速查表比对 | 直接定位 code |
   | 浏览器与设备 | 名称+版本 | 兼容类问题 |

3. **定性分级**：对照 `faq.md` §11 错误码速查表与 `ticketing.md` §3 分级标准定 P0–P3，创建工单（录入规范见 ticketing §2）。
4. **处置/流转**：FAQ 可解 → 直接发送标准话术；不可解 → 按升级路径流转（ticketing §5）。
5. **关单回访**：按 ticketing §7 满意度回访执行。

### 2.2 身份核实边界（重要）

- MVP **无客服后台**（架构无 admin 模块），客服原则上**看不到用户发票内容**；需要用户提供截图时，只索取与问题直接相关的最小范围，禁止索要整页发票明细。
- **任何场景不得索取用户密码**（系统无验证码体系，密码是唯一凭证）。
- 涉及账号归属的操作（密码重置、注销、换绑）走 §5 专项预案的核验流程。
- 交流中获得的发票信息按敏感信息对待：工单记录脱敏留存，结案后随工单归档，不用于其他用途。

### 2.3 常见场景处置速查

| 场景 | 首选动作 | 话术来源 |
| --- | --- | --- |
| 登录类（锁定/账密错/过期） | 自助话术 | FAQ Q09/Q10/Q14 |
| 忘记密码 | 人工重置预案 | §5.1 |
| 录入校验失败 | 自助话术 | FAQ Q22 |
| 汇总对不上 | 口径解释 | FAQ Q31 |
| 导出超限/乱码 | 自助话术 | FAQ Q33/Q32 |
| 附件三项限制 | 自助话术 | FAQ Q37–Q39 |
| 误删恢复 | 引导回收站 | FAQ Q43 |
| 超 30 天求恢复 | 红线话术（明确不可） | FAQ Q44/Q48 |
| 服务故障 | 公告口径 + 工单 | §5.2、FAQ Q50/Q51 |
| 功能建议 | 致谢 + 回流 | feedback-loop §4 |

## 3. 投诉 SOP

### 3.1 五步法：受理 → 安抚 → 定性 → 处置 → 回访

1. **受理**：任何不满表达均视为投诉受理，不打断、不辩解，先完整倾听/阅读。
2. **安抚**（首响即用）：

   > 非常抱歉给您带来了不好的体验，您的问题我们已经记录并会跟进到底。请您放心，我们会给您一个明确的处理结果。

3. **定性**：区分三类——
   - **A 类·故障投诉**（功能不可用/数据问题）→ 按影响映射工单 P1–P0，走技术修复；
   - **B 类·体验投诉**（不好用/文案困惑）→ P3/P2，回流 designer/pm；
   - **C 类·情绪升级**（对答复或态度不满）→ 客服负责人 1 个工作日内亲自回访。
4. **处置**：给出「现在能做什么 + 接下来会做什么 + 何时给下文」三段式答复；有 SLA 的以 SLA 为准。
5. **回访**：处置完成后 24 小时内回访确认满意度；投诉工单强制回访（普通工单抽样回访）。

### 3.2 话术边界（红线，逐条硬约束）

| # | 红线 | 正确做法 |
| --- | --- | --- |
| 1 | 不承诺「一定能恢复数据」 | 超 30 天明确说不可恢复（FAQ Q44/Q48）；30 天内引导自助恢复 |
| 2 | 不承诺具体修复时间 | 只承诺 SLA 内响应与通报节奏 |
| 3 | 不做法律层面的责任认定表述 | 「我们会认真核查并在 SLA 内给您处理进展」 |
| 4 | 不泄露内部细节（SQL/堆栈/拓扑/日志原文） | 只描述用户可见现象与结论 |
| 5 | 不索取密码、不要求提供他人发票信息 | 见 §2.2 |
| 6 | 不确认他人账号/记录的存在性 | 与系统 404 口径一致（INV_001） |
| 7 | 一线客服无现金/权益补偿承诺权 | 补偿统一走 §4 工具箱，超出部分升级负责人 |
| 8 | 不承诺范围外功能上线（OCR/查验/进项等） | 「已记录需求，二期评估」 |

### 3.3 升级触发

- 用户明确要求「找负责人/投诉到底」→ 直接升 C 类，负责人介入；
- 投诉涉及数据安全（疑似泄露/越权）→ **立即升 P0** 并转 ops 安全流程，客服只记录不讨论细节；
- 同一用户 7 日内 2 次以上投诉 → 负责人复盘个案。

## 4. 退款 / 补偿 SOP（一期免费口径 + 商业化占位）

### 4.1 退款（当前：无此场景）

一期完全免费、无支付通道，**不存在退款**。收到「退款/退费」咨询时统一话术：

> 票夹通目前是免费产品，没有向您收取任何费用，因此不涉及退款。如果您指的是某项付费服务的扣款，请核对是否为其他产品；如确有疑问，请提供扣款凭证，我们帮您排查。

（口径注记：误认/混淆场景按 P3 咨询处理；若发现有人冒用票夹通名义收费，**立即升 P1** 并通报负责人与 ops——属品牌冒用风险。）

### 4.2 补偿工具箱（非现金）

适用于：平台故障造成用户不便、数据需人工恢复、投诉安抚。按影响层级取用：

| 层级 | 适用 | 可用工具（一线可直接使用） | 需负责人审批 |
| --- | --- | --- | --- |
| 轻度 | 一般故障、体验受损 | 诚恳致歉 + 修复进展主动通报 | — |
| 中度 | 故障影响对账/交付（如导出数据错误） | 致歉信 + 优先修复 + 修复后一对一确认 | — |
| 重度 | 平台原因导致数据损失且无法自助恢复 | 以上全部 + 负责人亲自回访 + 数据恢复专项协助（tech 评估备份可用性，仅灾难级场景有效，见 4.3） | 是 |

致歉信模板：

> 尊敬的用户：因【故障现象】给您使用票夹通造成不便，我们深表歉意。该问题已于【时间】定位，【处理动作/工单号】，预计【SLA 口径的时间表述】处理完毕。您的数据安全是我们最重视的事项，感谢您的耐心与信任。——票夹通团队

### 4.3 数据损失类专项口径（与 ops 对齐，必须照读）

> 票夹通的定期备份用于服务器整机级灾难恢复（极端情况下最多回退 24 小时数据，恢复目标 2 小时内），**不支持针对单个用户、单条记录的定点恢复**。单条记录的误删保护是回收站 30 天机制。因此：30 天内的误删请自助恢复；超过 30 天的删除，包括彻底删除，技术上无法找回。建议您定期导出 CSV 自行留档。

（口径注记：RPO 24h / RTO 2h；此口径是 ops 明确要求向用户澄清的边界——**任何客服不得为安抚用户而暗示「后台备份可以找回单条数据」**。）

### 4.4 商业化后退款政策（占位骨架，当前不生效）

> ⚠️ 占位：一期无计费。商业化上线后必须回填以下内容并同步修订 `faq.md` 主题 H：
> - 退款适用场景与窗口期（如会员购买后 7 天内未使用核心功能可退）；
> - 退款流程（申请渠道 → 核验 → 原路退回时效）；
> - 补偿与退款的兑换关系（工具箱 vs 现金）；
> - 话术边界补充（退款承诺权限、支付渠道争议处理）。

## 5. 专项预案

### 5.1 忘记密码人工处置预案（Q1 未决期间的过渡方案）

**背景**：MVP 无自助找回（PRD §8.2 Q1），pm 预判为上线后高频问题，登录页已预留客服入口。

**流程**：

```
用户经登录页客服入口提交 → 一线按核验清单初审 → 建 P1 工单转 tech → tech 核验后执行重置（数据库层更新密码哈希，argon2id）→ 临时密码经注册邮箱/手机号渠道下发 → 用户首次登录后修改 → 工单关闭
```

**核验清单（满足任意两条）**：
1. 能准确提供注册标识 + 注册大致时间（误差 ±7 天）；
2. 能提供账号内至少 2 条发票的关键特征（抬头 + 大致金额/月份，由 tech 在数据库侧比对，客服不接触明细）；
3. 注册邮箱本身可收信（向该邮箱发确认函，回复确认即核验通过——邮箱注册用户优先用此条）。

**话术**：

> 当前版本暂未上线自助找回密码。为保护你的账号安全，我们需要先核实账号归属（核验项见下），核实通过后技术侧会为你重置密码，并通过你的注册邮箱/手机号下发临时密码，一般 1 个工作日内完成。重置后请立即登录并修改密码。

**目标时长**：首响 2 小时内、核验+重置 1 个工作日内（对齐 ticketing P1 SLA 的放宽版，因依赖人工核验）。

**风险与对冲**：核验凭据强度有限（无短信验证能力）→ ① 重置动作必须双人在线（tech 执行 + 负责人知悉）；② 重置后向原邮箱发送告警通知；③ 每次执行留痕入工单；④ 每次**计数并回流 feedback-loop 催办 Q1 决策**（该功能上线后本预案退役）。

### 5.2 系统故障公告预案

- **计划内（发布窗口周四 21:00，东八区）**：提前 24 小时（周三 21:00 前）在 FAQ 顶部与客服自动回复中挂公告：

  > 票夹通计划于本周四 21:00（北京时间）进行版本发布，期间服务可能出现几分钟短暂不可用，无需担心数据，稍后刷新即可。

- **计划外故障**：确认 ops 已告警后，客服口径统一为 FAQ Q51 话术；恢复后对受影响工单逐一回复「已恢复 + 致歉」；影响超 2 小时（RTO 口径）的，按 4.2 中度补偿执行并复盘。

### 5.3 账号注销人工流程

用户申请注销 → 核验归属（同 5.1 清单）→ 建 P2 工单 → 提醒先导出数据（FAQ Q49）→ tech 执行账号与数据删除（含附件）→ 15 个工作日内完成并回复 → 工单关闭。**注销不可撤销**，回复中必须书面确认用户已知悉。

### 5.4 安全事件上报（客服只做三件事）

遇用户报告「疑似看到别人数据 / 账号异地登录 / 收到冒充通知」：① **记录不承诺**（「我们已记录并转安全流程核查」）；② **立即升 P0**；③ 转 ops/tech 值班。客服不得自行验证、不得讨论细节、不得向用户透露任何排查手段。
